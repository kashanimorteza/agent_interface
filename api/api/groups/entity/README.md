# Entity Group

## Overview

Entity Group is the API Group that serves Entity Service over HTTP. It has one Adapter for every Entity Entity Service presents, and every Adapter has one Endpoint for every Action of that Entity's Child Service. An Endpoint lives at `<Base URL>/entity/<adapter>/<operation>`; its Handler calls its own Action and returns the Action's result and errors unchanged, and the Adapter is bound to its Entity, so a client never names the Entity in a request.

`BASE` below is the Base URL from the API's runtime Configuration (`url`), for example `http://127.0.0.1:8000/<key>`, and `JSON` is the header `Content-Type: application/json`.

```sh
curl -s "$BASE/entity/user/get_by_id/1"  # 200
```

```json
{"id": 1, "name": "Admin", "username": "admin", "password": "", "api_key": "", "is_active": true, "description": null}
```

## Endpoints

Every Adapter serves the same twelve Endpoints, derived from the Actions of its Child Service. A body Parameter is a member of one JSON object keyed by the Parameter's name, so an Endpoint with several body Parameters takes `{"filters": ..., "limit": ...}` and an Endpoint with one takes `{"entity": ...}`. A missing record returns `null`, never an error.

| Operation | Method | Path under the Adapter | Parameters | What it does |
|---|---|---|---|---|
| `add` | `POST` | `/add` | `entity` (body), `instance` (body, optional) | Store one complete new Entity instance and return the stored Entity. |
| `update` | `PUT` | `/update` | `entity` (body), `instance` (body, optional) | Replace every mutable Field of the stored record; null when no record exists. |
| `list` | `POST` | `/list` | `filters` (body, optional), `combination` (body, optional), `orders` (body, optional), `limit` (body, optional), `instance` (body, optional) | Return the Entities that match; a zero or negative limit means no limit. |
| `get_by_id` | `GET` | `/get_by_id/{id}` | `id` (path), `instance` (query, optional) | Return the Entity with the given id, or null. |
| `delete` | `DELETE` | `/delete/{id}` | `id` (path), `instance` (query, optional) | Remove the record and return the final deleted Entity, or null. |
| `enable` | `PATCH` | `/enable/{id}` | `id` (path), `instance` (body, optional) | Set only the activity Field to true and return the final Entity, or null. |
| `disable` | `PATCH` | `/disable/{id}` | `id` (path), `instance` (body, optional) | Set only the activity Field to false and return the final Entity, or null. |
| `count` | `POST` | `/count` | `filters` (body, optional), `combination` (body, optional), `instance` (body, optional) | Return the number of matching records. |
| `sum` | `POST` | `/sum` | `field` (body), `filters` (body, optional), `combination` (body, optional), `instance` (body, optional) | Return the total of a numeric Field, ignoring nulls, or zero. |
| `min` | `POST` | `/min` | `field` (body), `filters` (body, optional), `combination` (body, optional), `instance` (body, optional) | Return the smallest value of a comparable Field, ignoring nulls, or null. |
| `max` | `POST` | `/max` | `field` (body), `filters` (body, optional), `combination` (body, optional), `instance` (body, optional) | Return the largest value of a comparable Field, ignoring nulls, or null. |
| `truncate` | `DELETE` | `/truncate` | `instance` (query, optional) | Remove every record of the Entity, keep its Table, and return the deleted count. |

Each Entity below lists its Endpoints with their full Method and Path, and one example for each. The examples run in order against a freshly prepared Database, because they use the ids storage assigns. The examples of one Entity remove what they add; the last one, `truncate`, removes every record of the Entity and returns the deleted count, so it also removes the Entity's prepared records, and it fails with a 500 `ExecutionError` while other records still reference the Entity's records. Prepare the Database again after running them.

## Use

A client calls an Endpoint with the Method and Path from its table, at the Base URL. Requests with a body send `Content-Type: application/json`. Parameters travel in these forms:

- **An Entity** (`add`, `update`) is a JSON object of its Fields, as the Entity's table lists them. Decimals are text such as `"10.50"`, datetimes are ISO 8601 text with an offset, and a missing optional Field takes its default. `update` locates its record by the `id` in the object and replaces every mutable Field.
- **A Field** (`field`) is the Field's name, such as `"id"`; an unknown name is refused.
- **A Filter** is `{"field": ..., "operator": ..., "value": ...}` with an operator from `EQUALS`, `NOT_EQUALS`, `GREATER_THAN`, `GREATER_OR_EQUAL`, `LESS_THAN`, `LESS_OR_EQUAL`, `IN`, `CONTAINS`, `STARTS_WITH`, `ENDS_WITH`, `IS_NULL`, `IS_NOT_NULL`; a null test takes no value and `IN` takes a list. **An Order** is `{"field": ..., "direction": ...}` with a direction from `ASCENDING`, `DESCENDING`, ascending when left out. **A combination** is `AND`, `OR`.
- **An Instance** (`instance`) is its name, `SQLITE`; leave it out for the default Instance.

A request that cannot be served returns Problem Details (`application/problem+json`) whose `type` is the error's class name and whose status follows this table; every other Database error is a 500:

| `type` | Status |
|---|---|
| `InvalidInputError` | 422 |
| `LifecycleError` | 409 |
| `InactiveInstanceError` | 503 |
| `ConnectionFailureError` | 503 |
| every other Database error | 500 |

A request the API cannot read (a missing body member, a wrong type) is an `InvalidInputError` too.

```sh
curl -s -X POST "$BASE/entity/currency/list" -H "$JSON" -d '{"filters": [{"field": "decimal_digits", "operator": "EQUALS", "value": 0}]}'  # 200
```


## Verify

Start the API, then run this script from the API directory with `uv run python`. It reads the Base URL from the runtime Configuration, fetches the API's machine-readable description, and checks that every Entity Entity Service presents has an Adapter, that every Action of its Child Service has an Endpoint beneath it, and that nothing else is served beneath the Entity Group. It prints `all checks passed` when every check holds.

```python
import inspect
import json
import urllib.request
from pathlib import Path

import yaml
from logic.interface import Entity
from model.interface import entities

configuration = yaml.safe_load((Path.cwd() / "config.yaml").read_text())
base = configuration["url"]
with urllib.request.urlopen(f"{base}/openapi.json") as response:
    schema = json.load(response)
key = Path(base.split("//", 1)[1]).parts[1:]  # the URL Key, when there is one
served = {tuple(path.strip("/").split("/")[len(key) :]) for path in schema["paths"]}

expected = set()
for entity in entities:
    adapter = "".join("_" + c.lower() if c.isupper() else c for c in entity.__name__).lstrip("_")
    child = getattr(Entity.Service, entity.__name__)
    for action in (n for n in dir(child) if not n.startswith("_") and callable(getattr(child, n))):
        takes_id = "id" in inspect.signature(getattr(child, action)).parameters
        expected.add(("entity", adapter, action) + (("{id}",) if takes_id else ()))

assert served == expected, (sorted(served - expected), sorted(expected - served))
print("all checks passed")
```
