# Model

## Overview

Model is the shared domain vocabulary of the Trading Assistant: one authoritative definition for every domain concept the application works with. Every other part of the application reads these definitions instead of inventing its own idea of what a user, an account, or a position is.

Model is a Python library. You import it and work with the Domain Definitions it publishes. It sits at the bottom of the application: the database, logic, API, and presentation parts all depend on it, and it depends on none of them.

## Public Interface

Everything is imported from the `model` package.

```text
model
├── Domain Definitions
│   ├── User
│   ├── TradingPlatform
│   ├── Instance
│   ├── Currency
│   ├── Broker
│   ├── Asset
│   ├── AccountGroup
│   ├── Account
│   ├── TrailingGroup
│   ├── TrailingRule
│   ├── PartialGroup
│   ├── PartialRule
│   ├── ActionGroup
│   ├── Action
│   └── Position
└── Declaration types
    ├── DefinitionDeclaration
    ├── FieldDeclaration
    └── Relationship
```

Every Domain Definition offers the same operations:

| Operation | Accepts | Returns | Outcomes |
|---|---|---|---|
| Construct, `Definition(**values)` | Field values | An instance | Success, or `pydantic.ValidationError` naming each offending Field |
| `instance.serialize()` | nothing | The Plain Representation: a `dict` of simple named values | Success |
| `Definition.deserialize(data)` | A mapping of named values | An instance | Success, or `pydantic.ValidationError` naming each offending Field |
| `Definition.declaration()` | nothing | A `DefinitionDeclaration` describing the definition | Success |

### Construct an instance

```python
from model import User

user = User(
    name="Admin",
    username="admin",
    password="<password-placeholder>",
    api_key="<api-key-placeholder>",
)
print(user.name, user.is_active, user.id)
```

`id` is generated by whatever stores the record, so a new instance has none yet. Fields with a default take it when omitted. Unknown Fields, missing required Fields, wrongly typed values, and values that break a declared constraint are rejected.

### Turn an instance into its Plain Representation

```python
from model import User

user = User(name="Admin", username="admin", password="<password-placeholder>", api_key="<api-key-placeholder>")
plain = user.serialize()
print(plain)
```

The result is a `dict` of simple values that any standard JSON encoder accepts, for example `json.dumps(plain)`. A reference to another definition appears only as its reference value (for example `user_id: 1`), never as a nested object. Nothing is withheld: credential Fields are included, so decide what a response may reveal in the part of the application that sends it.

### Build an instance from a Plain Representation

```python
from model import User

user = User.deserialize(
    {
        "name": "Admin",
        "username": "admin",
        "password": "<password-placeholder>",
        "api_key": "<api-key-placeholder>",
    }
)
print(user.username)

try:
    User.deserialize({"name": "Admin"})
except ValueError as error:
    print("rejected:", error)
```

`deserialize` applies the same rules as constructing an instance, so it fails when the data breaks them. An exact decimal is given as a `Decimal`, an integer, or text such as `"1.10"`, and an instant is given as a timezone-aware datetime or its ISO text.

### Read a declaration

```python
from model import Account

declaration = Account.declaration()
print(declaration.name, declaration.persistence)
for field in declaration.fields:
    print(field.name, field.type, "optional" if field.optional else "not optional", "default" if field.has_default else "no default")
for relationship in declaration.relationships:
    print(relationship.field, "->", relationship.reference.__name__)
```

A declaration states, for the definition, whether it is `persistent` or `non-persistent` and its combined uniqueness sets. For each Field it states the logical type (`integer`, `string`, `boolean`, `decimal`, `float`, or `datetime`), whether the Field may have no value, its default, its length or precision when one is declared, whether it is an identity, generated, unique, or a credential and which at-rest treatment that credential needs. For each relationship it states the referenced definition itself (not its name), the Field that carries the reference, the Field it refers to, its cardinality, and whether it is optional.

### Domain Definitions

Every table below is read from the published declaration. Types are logical types: `decimal` values are exact and never accept a floating point number, `datetime` values are timezone-aware, and `float` is approximate.

### User

An independent user of the system. Each user has a separate set of settings, so new users can be added without affecting existing ones.

Persistence: `persistent`.

| Field | Type | Optional | Default | Constraints |
|---|---|---|---|---|
| `id` | integer | no | supplied by whatever generates it | identity; generated |
| `name` | string | no | required | unique |
| `username` | string | no | required | unique |
| `password` | string | no | required | credential, stored at rest by `hash` |
| `api_key` | string | no | required | credential, stored at rest by `hash` |
| `is_active` | boolean | no | `True` | - |
| `description` | string | yes | `None` | - |

### What Model does not do

Model stores nothing, performs no application behaviour, and offers no operations on stored data. It holds no initial data, opens no connection, and sends and receives nothing over a network. Saving, querying, and serving these definitions belong to the other parts of the application.

## Setup

Requirements: Python 3.14 and [uv](https://docs.astral.sh/uv/). The library depends on Pydantic 2 (2.13.5 at the time of writing).

From this directory:

```text
uv sync
```

To use Model from another project, add it as a dependency, for example `uv add ../model` from a sibling project. This library has no runtime configuration and needs no environment variables or secrets.

## Run

Model is imported, not started. After setup:

```text
uv run python -c "import model; print(sorted(model.__all__))"
```

## Verify

1. Every published name imports: `uv run python -c "import model; print(len(model.__all__))"` prints `18`.
2. The examples in this document run as written.
3. Source quality checks pass: `uv run ruff format --check src`, `uv run ruff check src`, and `uv run pyright`.

This library carries no test suite of its own.

## Troubleshooting

- **`Extra inputs are not permitted`**: the data contains a Field the definition does not declare. Remove it or check the spelling.
- **`Field required`**: a required Field is missing. See the tables above for which Fields are required.
- **`Input should be a valid integer` for a number given as text**: numbers, text, and flags are not coerced. Pass an `int`, a `str`, or a `bool` as the Field declares.
- **A decimal Field rejects a floating point number**: pass the value as text such as `"1.10"`, or as a `Decimal`.
- **A `datetime` Field rejects a value**: give a timezone-aware value, such as `"2026-09-19T12:30:00Z"`.
- **A credential Field keeps its surrounding spaces**: credentials are kept exactly as given; other text has surrounding whitespace removed.
- **`TypeError` when a class is defined**: a declaration is invalid, for example a relationship that names its target as text instead of carrying the definition, or a definition without `persistence`.
