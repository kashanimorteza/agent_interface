# Model

## Purpose and boundaries

The shared domain Model package for the Trading Assistant project. It provides the one logical definition of every domain entity — Users, Trading Platforms, Instances, Currencies, Brokers, Assets, Account Groups, Accounts, Trailing Groups and Rules, Partial Groups and Rules, Action Groups, Actions, and Positions — together with their fields, relationships, same-record domain rules, and declared initial data.

Model owns domain representation and same-record validation only. It does not persist data, enforce cross-record rules such as uniqueness, generate credential values, or implement application behaviour, API transport, or presentation — those belong to Database, Backend, and Frontend.

## Public interface

An import surface. Consumers install this package and import from its top-level namespace:

- Every resolved Model class (`User`, `TradingPlatform`, `Instance`, `Currency`, `Broker`, `Asset`, `AccountGroup`, `Account`, `TrailingGroup`, `TrailingRule`, `PartialGroup`, `PartialRule`, `ActionGroup`, `Action`, `Position`), each exposed exactly once.
- `GENERATE_SECURELY` — the sentinel marking a credential field in declared initial data whose actual value is generated by the responsible technical Component at insertion time.
- `INITIAL_DATA` — a mapping from each Model that declares initial records to its tuple of logical record declarations.
- `DomainModel` — the shared base class every Model derives from, exposing `credential_fields()` and the `unique_together` class attribute that declares composite uniqueness intent for that Model.

A field declared as carrying a credential value is marked in that field's schema metadata (`credential: True`); a field declared as carrying single-field uniqueness intent is marked the same way (`unique: True`). Neither marking is enforced by this package: same-record rules are validated on construction, but uniqueness across stored records and any rule requiring another record's data are guaranteed or evaluated by the Components that own that context.

## Dependencies

Pydantic, for the modeling and validation library used to express and construct each Model.

## Configuration

None. This package has no runtime configuration or secrets of its own.

## Installation and startup

Managed as an isolated `uv` project. From this directory:

```bash
uv sync
```

There is no startup step; the package is a library imported by other layers.

## Usage examples

```python
from decimal import Decimal
import my_model as m

user = m.User(name="Admin", username="admin", password="...", api_key="...")

# Declared initial data, ready for a Database insertion step to generate
# credential values and persist the records.
for record in m.INITIAL_DATA[m.User]:
    ...  # record["password"] is m.GENERATE_SECURELY until Database generates it

# Same-record validation is enforced on construction.
try:
    m.Currency(user_id=1)  # missing required "code"
except Exception:
    ...
```
