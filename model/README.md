# Model

The `model` package is the Trading Assistant's Model Component: the authoritative logical
Domain Definitions for the system's domain. It preserves domain identity, fields,
relationships, and rules as one coherent boundary with an explicit, stable Public Interface.

Model owns domain meaning only. It never owns persistence, transport, presentation, or
workflow orchestration — those belong to the Database, Backend, and Frontend Components.

## Public surface

Everything a consumer needs is importable directly from `model`:

```python
from model import (
    Account,
    AccountGroup,
    Action,
    ActionGroup,
    Asset,
    Broker,
    Currency,
    Instance,
    ModelBase,
    PartialGroup,
    PartialRule,
    Position,
    TimezoneAwareDatetime,
    TradingPlatform,
    TrailingGroup,
    TrailingRule,
    UniqueConstraints,
    User,
)
```

- **15 Domain Definitions** — `User`, `TradingPlatform`, `Instance`, `Currency`, `Broker`,
  `Asset`, `AccountGroup`, `Account`, `TrailingGroup`, `TrailingRule`, `PartialGroup`,
  `PartialRule`, `ActionGroup`, `Action`, `Position` — each a Pydantic model carrying
  exactly the fields, relationships, and rules the Target defines for it.
- **`ModelBase`** — the shared Model Foundation every Domain Definition builds on: unknown
  fields are rejected, assignment is re-validated, and string fields are stripped of
  incidental whitespace.
- **`TimezoneAwareDatetime`** — a datetime type that rejects a naive (timezone-less) value;
  used wherever the Target requires an absolute instant (for example `Position.date`).
- **`UniqueConstraints`** — the declared type of a Domain Definition's
  `UNIQUE_CONSTRAINTS` class attribute: a tuple of field-name tuples describing which field
  combinations must be unique. Model declares these constraints; enforcing them across
  concurrent writes is the Database Component's responsibility.

Credential fields (for example `User.password`, `User.api_key`, `Instance.password`,
`Account.password`) are marked in their `Field(...)` declaration with
`json_schema_extra={"credential": True}`, so a consumer can discover which fields carry
credential meaning without hardcoding a field-name list. Model itself stores no at-rest
protection — that resolved treatment (hash, encrypted, ...) is applied by Database.

## Setup

Requires Python 3.13+ and [uv](https://docs.astral.sh/uv/).

```bash
cd model
uv sync
```

## Installation (as a dependency)

Another Component in this repository (for example `database`) depends on this package
through its own `pyproject.toml`:

```toml
[project]
dependencies = ["model"]

[tool.uv.sources]
model = { path = "../model" }
```

## Configuration

Model has no runtime configuration of its own — it is a pure, side-effect-free domain
library. There is nothing to configure and no environment variable to set.

## Use

```python
from model import User

# id is generated by the persistence layer, so it is optional at construction time.
admin = User(name="Admin", username="admin", password="change-me", api_key="generated-key")

assert admin.is_active is True  # declared default
assert admin.id is None  # not yet assigned by storage

# Every Domain Definition round-trips through JSON without loss.
restored = User.model_validate_json(admin.model_dump_json())
assert restored == admin

# Declared uniqueness is discoverable without re-reading the Target.
assert User.UNIQUE_CONSTRAINTS == (("name",),)

# Credential fields are discoverable the same way.
assert User.model_fields["password"].json_schema_extra == {"credential": True}
```

Every Domain Definition rejects an unknown field and re-validates on attribute assignment:

```python
from pydantic import ValidationError

try:
    User(name="Admin", username="admin", password="x", api_key="y", extra_field="nope")
except ValidationError:
    ...  # rejected: Model accepts only its declared fields
```

## Troubleshooting

- **`ValidationError: Extra inputs are not permitted`** — a field name does not match the
  Target's declared field set for that Domain Definition; check spelling against this
  README's field list or the class definition, not against a prior version of the Target.
- **`ValidationError` on a `date` field** — `Position.date` (and any other
  `TimezoneAwareDatetime` field) requires a timezone-aware `datetime.datetime`; construct
  it with `tzinfo=datetime.UTC` or another explicit offset.
- **`id` is `None` after construction** — expected: `id` is a `generated: true` field
  supplied by the Database Component at persistence time, not by Model.
