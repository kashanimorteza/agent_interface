# Database

## Overview

Database stores the Entities that Model publishes and offers one stable way to use them. A consumer imports
`database.interface`, creates one `Database`, and calls Operations that take Entities, Field references, and
vocabulary members as imported values, never as text. Core validates every request, and one Engine unit does
the storage work for the active Instance. Connection details, configuration, and storage paths are never
published.

```python
from database.interface import Database
from model.interface import User

db = Database()
user = db.add(User(name="Ada", username="ada", password="example-password", api_key="example-key"))
print(user.id)  # generated by storage
print([stored.name for stored in db.list(User)])  # ['Admin', 'Ada']
```

## Interface

`database.interface` is the only public entry point. It publishes exactly these contracts and nothing else:

| Contract | What it is |
|---|---|
| `Database` | The class a consumer creates once. Every Operation and Lifecycle Command is a method of it. |
| `DatabaseInstance` | The enumeration of the active configured Instances. It carries no connection values. |
| `Filter` | An immutable condition: a Field reference of an Entity, an operator member, and a value. |
| `FilterOperator` | The comparison operators (below). |
| `FilterCombination` | How Filters combine: `AND` or `OR`. |
| `Order` | An immutable ordering: a Field reference and a direction member. |
| `OrderDirection` | `ASCENDING` or `DESCENDING`. |
| `CommandResult` | The outcome of `execute_command`. |
| `LifecycleResult` | The outcome of a Lifecycle Command. |
| `DatabaseError` and seven failure-kind errors | See Errors below. |

An Entity is passed as the Entity itself, an instance or the class imported from Model, and a Field is passed as the
Entity's own Field reference such as `Currency.code`. A name written as text is refused with `InvalidInputError`
before any storage is touched. Every Operation and Lifecycle Command takes an optional `DatabaseInstance` as its
last parameter; without one the call runs on the default Instance.

```python
from database.interface import (
    CommandResult, Database, DatabaseInstance, Filter, FilterCombination, FilterOperator,
    LifecycleResult, Order, OrderDirection,
)
from model.interface import Account, Asset, Broker, Currency, Position, User

db = Database()
```

### Vocabulary

`FilterOperator` has exactly these members. A Filter with a text operator needs a textual Field; the range operators
need a comparable Field; the null tests take no value; `IN` takes a collection.

| Member | Selects records whose Field |
|---|---|
| `EQUALS` / `NOT_EQUALS` | equals / differs from the value |
| `GREATER_THAN` / `GREATER_OR_EQUAL` | is greater than / at least the value |
| `LESS_THAN` / `LESS_OR_EQUAL` | is less than / at most the value |
| `IN` | equals one of the given values |
| `CONTAINS` / `STARTS_WITH` / `ENDS_WITH` | contains / starts with / ends with the text (case-sensitive) |
| `IS_NULL` / `IS_NOT_NULL` | is null / is not null |

`FilterCombination` has `AND` and `OR`; `OrderDirection` has `ASCENDING` and `DESCENDING`. Decimal Fields are
compared by their exact numeric value, so `10.5` and `10.50` are equal.

Defaults: an omitted combination is `AND`; omitted Orders sort by `id` ascending; an Order without a direction
ascends; an omitted limit means no limit, and a zero or negative limit also means no limit. Supplied Orders
replace the default order and apply in the order given. Results with equal keys follow ascending `id`.

### Entity Operations

Each takes the Entity first and the optional `instance` last. A missing record returns `None`, never an error.

**`add(entity, instance=None)`** stores one complete new Entity instance and returns the stored Entity, including
its generated `id`.

```python
broker = db.add(Broker(name="Second broker", user_id=1))
print(broker.id)  # 2
```

**`update(entity, instance=None)`** replaces every mutable Field of the stored record that the Entity's `id`
locates and returns the stored Entity, or `None`. It never changes `id` or another immutable Field.

```python
broker.description = "Backup broker"
broker = db.update(broker)
print(broker.description)  # Backup broker
```

**`list(entity, filters=None, combination=None, orders=None, limit=None, instance=None)`** returns the matching
Entities.

```python
rows = db.list(
    Currency,
    filters=[Filter(Currency.decimal_digits, FilterOperator.EQUALS, 2)],
    orders=[Order(Currency.code, OrderDirection.DESCENDING)],
    limit=3,
)
print([currency.code for currency in rows])  # ['USD', 'NZD', 'GBP']
```

**`get_by_id(entity, id, instance=None)`** returns the Entity with that `id`, or `None`.

```python
print(db.get_by_id(User, 1).name)  # Admin
print(db.get_by_id(User, 999))  # None
```

**`delete(entity, id, instance=None)`** removes the record and returns the final deleted Entity, or `None`.

```python
print(db.delete(Broker, broker.id).name)  # Second broker
```

**`enable(entity, id, instance=None)`** and **`disable(entity, id, instance=None)`** set only `is_active` and return
the final Entity, also when it already had that value, or `None`.

```python
print(db.disable(Currency, 1).is_active)  # False
print(db.enable(Currency, 1).is_active)  # True
```

**`count(entity, filters=None, combination=None, instance=None)`** returns the number of matching records.

```python
print(db.count(Currency, filters=[Filter(Currency.country, FilterOperator.CONTAINS, "United")]))  # 2
```

**`sum(entity, field, filters=None, combination=None, instance=None)`** returns the total of a numeric Field,
ignoring nulls, or zero when nothing matches. **`min(...)`** and **`max(...)`** take the same parameters for a
comparable Field and return the smallest or largest value, ignoring nulls, or `None`.

```python
print(db.sum(Asset, Asset.digits))  # 15
print(db.min(Asset, Asset.point_size), db.max(Asset, Asset.point_size))  # 0.0001 0.01
```

**`truncate(entity, instance=None)`** removes every record of the Entity, keeps its Table, and returns the
deleted count. It affects no other Entity.

```python
print(db.truncate(Position))  # 0
```

### Database-wide Operation

**`execute_command(command, parameters=None, instance=None)`** runs a native command in the Instance's query
language with bound parameters, including a schema change, and returns a `CommandResult`.

```python
result = db.execute_command('select code, symbol from "Currency" where code = ?', ["EUR"])
print(result.success, result.columns, result.rows[0]["symbol"])  # True ('code', 'symbol') €
```

### Lifecycle Commands

**`create_tables(instance=None)`**, **`insert_initial_data(instance=None)`**, and **`prepare(instance=None)`**
return a `LifecycleResult`. They are explained under Lifecycle.

```python
print(db.prepare().success)  # True
```

### Results

`CommandResult` has `rows` (read-only row mappings, or `None`), `affected` (a count, or `None`), `columns` (ordered
names, or `None`), `success`, `message`, and `instance` (the `DatabaseInstance` used). `LifecycleResult` has
`command`, `instance`, `success`, `affected` (the processed Table or record count, or `None`), and `message`. Both
are immutable.

### Errors

Every error derives from `DatabaseError`, and none carries a connection value.

| Error | Raised when |
|---|---|
| `ConfigurationError` | the configuration or a selected Instance is invalid |
| `InactiveInstanceError` | an inactive Instance is selected |
| `InvalidInputError` | an input, Entity, or Field is invalid, for example text where an imported value is required |
| `DeclarationMismatchError` | a stored row or Table does not match the Entity's Declaration |
| `ConnectionFailureError` | the Instance cannot be reached |
| `ExecutionError` | a request fails or violates a constraint |
| `LifecycleError` | a Lifecycle Command leaves an incomplete state |

## Instances

`DatabaseInstance` has one member for every active configured Instance and none for an inactive one. This
Database has one active Instance:

| Member | Instance | State |
|---|---|---|
| `DatabaseInstance.SQLITE` | SQLite | active, and the default |

A second Instance, PostgreSQL, is configured but inactive, so it has no member and cannot be selected. A call
without a `DatabaseInstance` runs on the default Instance:

```python
print(db.get_by_id(User, 1).name == db.get_by_id(User, 1, DatabaseInstance.SQLITE).name)  # True
```

The SQLite Instance stores its data in a file that the Database owns, inside the Database's own `db` directory.
The file is created the first time storage is needed, loading the Interface creates nothing, and no path or
credential is ever returned or accepted through the Interface. To change which Instances are active, change the
configuration and regenerate the Database; a mismatch between the configuration and `DatabaseInstance` fails
loading with `ConfigurationError`.

## Setup

Requirements: Python 3.14 or newer, [uv](https://docs.astral.sh/uv/), and the sibling `model` project, which the
Database depends on.

```sh
cd database
uv sync
```

`uv sync` creates the isolated environment in `.venv` from `pyproject.toml` and `uv.lock`. Run Python in it with
`uv run python`. Generation runs Prepare automatically on the default Instance, so a generated Database already
has its Tables and Initial Data. The Database must be used from its own project directory (an editable install),
because its configuration and storage belong to it.

## Use

Everything below goes through `database.interface`, with Field references and enumeration members, never text.

Filters combine with `AND` unless `FilterCombination.OR` is given:

```python
rows = db.list(
    Currency,
    filters=[
        Filter(Currency.code, FilterOperator.EQUALS, "USD"),
        Filter(Currency.code, FilterOperator.EQUALS, "EUR"),
    ],
    combination=FilterCombination.OR,
)
print(sorted(currency.code for currency in rows))  # ['EUR', 'USD']
```

An Entity read from storage carries its stored `id`, so a record can be read, changed, and saved back:

```python
currency = db.get_by_id(Currency, 2)
print(currency.code, currency.symbol)  # EUR €

note = db.add(Broker(name="Scratch broker", user_id=1))
note.description = "read, changed, and saved back"
print(db.update(note).description)  # read, changed, and saved back
db.delete(Broker, note.id)
```

A failure keeps its own error kind and can be caught on its own or as `DatabaseError`:

```python
from database.interface import InvalidInputError

try:
    db.list("Currency")
except InvalidInputError as error:
    print("refused:", error)
```

## Lifecycle

Lifecycle Commands prepare storage and are separate from the Operations. Each takes an optional `DatabaseInstance`
and returns a `LifecycleResult`; none runs implicitly except Prepare after generation.

- **`create_tables`** creates one Table for every Entity of Model's Entity Collection, using only those Entities
  and their Declarations. A Table that already matches is left unchanged, so it can be repeated. If an existing
  Table differs from its Declaration, the command stops, reports the difference, returns an unsuccessful result,
  and changes nothing; the Database never alters a Table by judgment.
- **`insert_initial_data`** validates every configured Initial Data record through its Entity, inserts each missing
  record atomically, skips a record that is already present and identical, and fails clearly on a conflicting one
  without overwriting or deleting anything. It succeeds with zero affected only when no Initial Data is
  configured.
- **`prepare`** runs `create_tables` and then `insert_initial_data`, and stops without inserting when
  `create_tables` does not succeed.

Run them by hand from the Database directory; each entry point only calls the command through the Interface, prints
its `LifecycleResult`, and exits with a non-zero status when the result is unsuccessful:

```sh
uv run python scripts/create_tables.py
uv run python scripts/insert_initial_data.py
uv run python scripts/prepare.py
```

Generation runs `prepare` on the default Instance only; other Instances are prepared only when selected explicitly.

## Verify

Run this script from the Database directory with `uv run python`. It checks the public import, Instance selection,
the query vocabulary, each capability group, the persistent file location, and repeatable Lifecycle Commands. It
removes the one record it adds, and it prints `all checks passed` when every check holds.

```python
import subprocess
import sys
from pathlib import Path

import database.interface as interface
from database.interface import (
    Database, DatabaseInstance, Filter, FilterCombination, FilterOperator, Order, OrderDirection,
)
from model.interface import Broker, Currency, User

# Public import: exactly the published contracts, and loading creates nothing.
PUBLIC = {
    "Database", "DatabaseInstance", "Filter", "FilterOperator", "FilterCombination", "Order",
    "OrderDirection", "CommandResult", "LifecycleResult", "DatabaseError", "ConfigurationError",
    "InactiveInstanceError", "InvalidInputError", "DeclarationMismatchError",
    "ConnectionFailureError", "ExecutionError", "LifecycleError",
}
assert {name for name in vars(interface) if not name.startswith("_")} == PUBLIC
assert interface.InvalidInputError.__mro__[1] is interface.DatabaseError

# Query vocabulary: closed member sets, members named like their values.
assert [member.name for member in FilterCombination] == ["AND", "OR"]
assert [member.name for member in OrderDirection] == ["ASCENDING", "DESCENDING"]
assert len(FilterOperator) == 12
assert all(member.value == member.name for member in FilterOperator)

# Instance selection: the default Instance and a named Instance are the same active Instance.
db = Database()
assert [member.name for member in DatabaseInstance] == ["SQLITE"]
assert db.get_by_id(User, 1).name == db.get_by_id(User, 1, DatabaseInstance.SQLITE).name

# Persistent file location: inside the Database's own storage directory.
storage = Path(interface.__file__).resolve().parents[1] / "db" / "application.db"
assert storage.is_file()

# Capability groups, used only through the Interface.
broker = db.add(Broker(name="Verification broker", user_id=1))
assert broker.id is not None and db.get_by_id(Broker, broker.id).name == broker.name
broker.description = "checked"
assert db.update(broker).description == "checked"
assert db.disable(Broker, broker.id).is_active is False and db.enable(Broker, broker.id).is_active
assert db.count(Broker, [Filter(Broker.name, FilterOperator.STARTS_WITH, "Verification")]) == 1
assert [c.code for c in db.list(Currency, orders=[Order(Currency.code)], limit=1)] == ["AUD"]
assert db.sum(Currency, Currency.decimal_digits) == 14
assert db.min(Currency, Currency.code) == "AUD" and db.max(Currency, Currency.code) == "USD"
assert db.delete(Broker, broker.id).name == "Verification broker"
assert db.get_by_id(Broker, broker.id) is None
assert db.execute_command("select count(*) as n from \"Currency\"").rows[0]["n"] == 8

# Repeatable Lifecycle Commands: running them again changes nothing.
before = db.count(Currency)
for command in (db.create_tables, db.insert_initial_data, db.prepare):
    first, second = command(), command()
    assert first.success and second.success and first.affected == second.affected
assert db.count(Currency) == before

# The same commands from the manual entry points.
scripts = Path(interface.__file__).resolve().parents[1] / "scripts"
for name in ("create_tables", "insert_initial_data", "prepare"):
    run = subprocess.run([sys.executable, str(scripts / f"{name}.py")], capture_output=True, check=False)
    assert run.returncode == 0

print("all checks passed")
```

## Troubleshooting

- **`ConfigurationError` mentioning DatabaseInstance members.** The active Instances in the configuration no longer
  match the generated `DatabaseInstance`. Regenerate the Database after changing which Instances are active. An
  Instance that is configured but inactive cannot be selected.
- **`ConfigurationError` saying the Database must run from its own Component.** The Database was loaded from an
  installed copy. Use it from its project directory with `uv sync` and `uv run python`.
- **`create_tables` or `prepare` returns an unsuccessful result saying a Table differs from its Declaration.** An
  existing Table does not match its Entity. The Database stops and changes nothing; it never alters a Table by
  judgment. Decide what to do with the existing storage, then run the command again.
- **`insert_initial_data` returns an unsuccessful result naming a conflict.** A stored record shares unique values with
  a configured record but differs from it. Nothing was inserted. Resolve the stored record, then run it again.
- **Empty values in Initial Data.** Values that the Target does not give concretely are stored as empty strings, on
  purpose. Update them after preparation.
- **`ConfigurationError` for a selected Instance.** The Instance was not passed as a `DatabaseInstance` member, for
  example it was written as text, or it is not configured. Import a member and pass it as the last parameter.
- **`InvalidInputError`.** An Entity, Field, operator, or combination was passed as text, a Field belongs to another
  Entity, an operator does not fit the Field, or a value does not match the Field's Type. Pass imported values.
- **`ExecutionError`.** A request violated a constraint, for example a duplicate unique value or a reference to a
  missing record, or a native command was invalid. The failed change left no partial data.
- **`ConnectionFailureError`.** The Instance could not be reached; check that the Database's storage is writable.
- **`DeclarationMismatchError`.** A stored row or value does not satisfy its Entity's contract, for example a stored
  value that cannot become its Field's Type. It is reported with the Entity named and the value hidden, never
  repaired.
